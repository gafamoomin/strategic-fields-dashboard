# 17の戦略分野 × 契約学科 ダッシュボード

政府「17の戦略分野」の官民投資額（想定）と、2026年7月7日にNEDOが採択した契約学科5件の対応関係を可視化する。

- 分野単位／製品・技術単位の切り替え
- 横棒グラフ／ツリーマップの切り替え
- 再掲を除く／含むの切り替え
- 契約学科つきの一覧表

## 動かす

```bash
npm install
npm run dev        # http://localhost:3000
```

その他のコマンド:

```bash
npm run build      # 本番ビルド
npm run typecheck  # 型チェックのみ
```

Node.js 18.18 以上が必要。

## 構成

```
app/
  layout.tsx          メタデータと globals.css の読み込み
  page.tsx            サーバーコンポーネント。Dashboard を置くだけ
  globals.css         リセットとフォーカスリング
components/
  Dashboard.tsx       "use client"。UIとグラフはすべてここ
data/
  strategic-fields.ts 唯一のデータソース。型定義も同居
```

依存は next / react / recharts のみ。CSSフレームワークは入れていない（`Dashboard.tsx`
の `C` オブジェクトに色を集約し、インラインスタイルで組んでいるため）。
Tailwind を足したい場合は `npx tailwindcss init -p` から通常どおり導入できる。

## データベースについて

**不要。** データは64行の静的な値で、更新は年に数回あるかどうか。
`data/strategic-fields.ts` を import しているだけなので、ビルド時にすべて解決され、
`npm run build` の結果は `○ (Static)` ＝ 事前生成された静的HTMLになる。
DBを挟むと、接続・環境変数・レイテンシ・障害点が増えるのに得るものがない。

データを直す手順は git そのものになる:

```bash
# data/strategic-fields.ts を編集
git commit -am "GXケミカルの契約学科を更新"
git push        # Vercel が自動で再デプロイ
```

差分がレビューでき、履歴が残り、間違えたら revert できる。契約学科のような
「後から一次情報が出てきて推定を上書きする」データとは相性がいい。

DBが要るのは次のいずれかが発生したときだけ:

| きっかけ | 必要になるもの |
|---|---|
| ブラウザ上でデータを編集したい | DB + 認証 |
| 大学ごとにログインさせて出し分けたい | 認証（DBは任意） |
| 誰がどこを見たかを記録したい | 分析ツール（DBは任意） |
| 行数が数千を超える／頻繁に変わる | DB |

なお `npm run build` 時点の First Load JS は 219 kB。うち大半が Recharts。

## 数値の扱い

UIの「このデータについて」に同じ内容を表示している。要点だけ再掲する。

- **再掲2品目**：バイオ医薬品・再生医療等製品等（20.8兆円）とグリーン鉄（4.2兆円）は原典で2分野に
  同一項目として掲載される。原典は本体側を定めていないため、野村證券の整理に合わせ
  **バイオ医薬品・再生医療等製品等＝合成生物学・バイオ**、**グリーン鉄＝資源・エネルギー安全保障・GX**
  を本体とした。`isRestated` が重複側。分野合計は `total`（再掲含む）と `totalNet`（再掲除く）の2系統。
  17分野の `totalNet` を足すと 395.3 兆円、`total` を足すと重複25.0兆円ぶん多い 420.3 兆円になる。
  面積で全体との比を読むツリーマップには必ず `totalNet` を使うこと。
- **総額**：政府の公表値は「2040年度までの累計で370兆円超（「主要な製品・技術等」間での重複を排除）」。
  395.3 兆円は62品目の単純合計にすぎず、政府公表値ではない。原典は両者の突合を示していないため、
  差の25.3兆円は説明できない。ヒーローに単純合計を掲げないこと。
- **対象期間**：到達年度は品目ごとに異なる。60品目 395.3兆円の内訳は 2040年度まで 315.9（79.9%）、
  2035年度まで 42.1（10.7%）、2033年度まで 33.7（8.5%）、2030年度まで 2.6、2034年度まで 1.0。
  **約2割は2040年度までの累計になっていない**。原典が「超」を付けている理由の一つがこれ
  （「官民投資額が2040年度まで記載されていない『主要な製品・技術等』についてはその部分は加算されていない」）。
  グラフは期間の異なる数字を並べている点に注意。
- **金額未確定**：艦艇（新安保3文書を反映）とLNG運搬船（今後精査）は `amount: null` で合計・順位から除外。
- **順位**：金額が確定している60品目の競争順位（同額は同順位、次はその数だけ飛ばす）。
  母集団は「品目」であって「金額の種類」ではない。ここを `set` にすると dense rank になり静かに壊れる。
- **見出しの数字**：一覧で印が付く製品・技術（`contracts.length > 0`）と、その投資額合計に揃えている。
  5製品・技術／23.6兆円。`Dashboard.tsx` 冒頭の `TAGGED` から算出しており、ハードコードしていない。
- **対応づけの前提**：契約学科と分野・製品・技術の対応関係は、政府・NEDO・各大学のいずれも公表していない。
  すべて公開情報からの推定であり、`MAPPING_NOTE` として1か所に持ち、ヒーロー・一覧・注釈で示す。
  以前はリンクごとに `role`（主／副）と `confidence`（確定／推定／推定（弱））を持たせていたが、
  一覧では表示せずホバーにしか出ておらず、前提を一言で書けば足りるため廃止した。
  代わりに `basis`（根拠）を必須とし、一覧に「根拠」列として出している。読み手が自分で判断できる形にする。
- **リンクを足すときの基準**：分野名や語の連想で紐づけないこと。新潟大学 × バーティカルAI を
  「AIという語がカリキュラムにある」だけで紐づけて取り消した（内閣府 AI戦略本部の定義では
  バーティカルAI＝領域特化型基盤モデルの開発・実装であり、AIを使う人材の育成は該当しない）。
  紐づける前に、その製品・技術の政府側の定義を当たること。根拠が書けないなら足さない。
- **出典**：`PROGRAMS[].sources` は配列。`label` とリンク先が一致していることを必ず確認すること
  （NEDOのリリースを指す label に大学のURLを貼る、といった不一致を過去に作った）。
  採択の事実を示す出典を先頭に置き、推定の根拠として参照しているだけの資料は `note` にその旨を書く。
  東北大学と東京大学は、当事業に関する大学・企業側のリリースが確認できておらず、採択の一次情報はNEDOのリリースのみ。

分野合計17件・品目順位60件とも、野村證券の記事表と一致することを確認済み。
データを変更したら、この一致が崩れていないかを必ず確認すること。
